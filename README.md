# Частотний аналіз літер

Навчальний проєкт, варіант 7, лабораторні роботи 1–2 з професійної практики програмної інженерії. Поточна технічна версія: **0.1.11**.

Програма підраховує кожну літеру в тексті без урахування регістру й виводить символьну стовпчикову діаграму. Коректний результат містить точні кількості кожної літери, загальну кількість та кількість різних літер.

## Середовище й запуск

Потрібен Python 3.10 або новіший. Сторонніх бібліотек і окремого збирання немає. У Windows за потреби замініть `python` на `py -3`.

```text
python main.py
Введіть текст: Абба! 123
Літера | Діаграма (максимум 50 символів; поріг: 1) | Кількість
а ################################################## 2
б ################################################## 2
Усього літер: 4; різних: 2
```

Файл: `python main.py --file text.txt`. Файл повинен мати кодування UTF-8 (BOM допускається); обробляється весь багаторядковий текст. Довідка: `python main.py --help`.

## Правила підрахунку

- Нормалізація Unicode NFC об'єднує складені символи, наприклад `і` + діакритичний знак у `ї`.
- Враховуються Unicode-літери, зокрема українські ґ, є, і, ї. Пробіли, цифри й пунктуація не рахуються.
- Літери впорядковані за Unicode-кодом; латинська `a` та кирилична `а` різні.
- Стовпчики масштабуються пропорційно: найбільша частота має рівно 50 `#`. Округлення до найближчого цілого, половини вгору; мінімум один знак для додатної частоти. Числова кількість завжди точна.
- Помилкові дані: порожній текст, текст без літер, недоступний файл, файл не в UTF-8. Повідомлення друкується без traceback, код завершення 2. Успішне завершення має код 0.

## Перевірка

```text
python -m py_compile main.py
python -m unittest -v
```

Тести охоплюють регістр, українську абетку, нормалізацію Unicode, змішані абетки, діаграми, порожній ввід, файли UTF-8, хибне кодування й відсутній файл.

## ЛР2 — задача А

[Задача #1](https://github.com/st1ksi/letter-frequency-labs/issues/1): масштаб діаграми. Для `аааабб` стовпчики мають довжини 50 та 25, кількості 4 та 2. Гілка `lr2-scale-histogram` створена від коміту ЛР1 одночасно з гілкою задачі Б.

## ЛР2 — задача Б

[Задача #2](https://github.com/st1ksi/letter-frequency-labs/issues/2): параметр `--min-count N` відбирає літери з частотою не нижче N. Типово 1, допустиме лише ціле число від 1. Для `ааааббв` і `--min-count 2` показано а=4 та б=2; в=1 приховано. Загальні підсумки стосуються всього тексту. Якщо поріг вищий за всі частоти, програма пояснює відсутність результатів і завершується з кодом 0. Поріг 0, від’ємний або нецілий — помилка з кодом 2. Гілка створена від тієї ж точки ЛР1, що й гілка задачі А.

## Об’єднання ЛР2

[PR #3](https://github.com/st1ksi/letter-frequency-labs/pull/3) реалізує масштабування;
[PR #4](https://github.com/st1ksi/letter-frequency-labs/pull/4) — поріг частоти.
Обидві гілки починалися від `121b0f6`. Після першого злиття друге спричинило справжній конфлікт `render_histogram` та супровідних файлів. Результат поєднує відбір, масштабування й обидва набори тестів.

Для `python main.py --min-count 2` та тексту `ааааббв` показано 50 знаків для а=4 і 25 для б=2; в=1 приховано. Усього в початковому тексті 7 літер і 3 різні. Поріг 4 залишає а з 50 знаками; поріг 5 дає повідомлення про відсутність збігів.

`python -m unittest -v` виконує 26 перевірок. Взаємне ревью з партнером, якого призначає викладач, ще не проведено: партнера поки не визначено. Самоперевірка не позначена як партнерське ревью.
